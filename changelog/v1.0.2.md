# v1.0.2

## Proxy API — Hashrate unit parameter

The subnet Proxy API now supports an optional `unit` parameter on worker statistics endpoints:

- `GET /api/workers/stats?unit=gh|mh`
- `GET /api/workers/timerange?unit=gh|mh`

**Default is unchanged** (`gh` → GH/s). Existing validators and integrations continue to work without modification.

See [Proxy API documentation](../docs/proxy-api.md) for request examples and response field details.

## What changed for validators

- **No action required** for the bundled `ProxyPoolAPI` client — it still receives GH/s by default.
- Custom integrations may pass `unit=mh` if MH/s is preferred; always read `hash_rate_unit` from the response.

## What changed for third-party integrators

- Optional `unit=mh` returns hashrate fields in MH/s (`hash_rate_unit: "MH/s"`).
- Numeric values scale by 1000× relative to GH/s (e.g. 2.05 GH/s → 2050 MH/s).
- Shares, share_value, online hours, and other non-hashrate fields are unaffected.
